# 09 — Self-Supervised Pretraining on Graphs
*Contrastive learning, masked autoencoding, and the pretraining objectives that power the GFM era.*

This chapter is the bridge from "train a GNN on a single graph" to "pretrain a GFM on a large corpus of graphs." The methods here are the same pretraining techniques used in NLP (BERT, GPT) and vision (MAE, DINO), adapted to graph data.

## 9.1 Why pretrain?

In NLP and vision, pretraining on a large corpus with a self-supervised objective gives a model that can be finetuned to many downstream tasks with little data. The question for graphs: **can we do the same?**

The challenge: graphs are not "IID samples" — each graph is a structured object. A corpus of graphs is a set of structured objects, each with different size, topology, and feature distribution. The pretraining objective must be:
- **Permutation invariant** for graph-level tasks.
- **Permutation equivariant** for node-level tasks.
- **Agnostic to graph size**.

The methods below are the main solutions. They are categorised into:
- **Contrastive**: pull positive pairs together, push negative pairs apart.
- **Generative**: reconstruct masked parts of the input.
- **Predictive**: predict some property of the input (e.g., a structural property).
- **Hybrid**: combinations of the above.

## 9.2 Contrastive learning: the framework

**Setup.** Given an "anchor" sample $x$, find a "positive" $x^+$ and a set of "negatives" $x_1^-, x_2^-, \ldots, x_K^-$. The model is trained so that $x$ and $x^+$ are close in embedding space, while $x$ and each $x_i^-$ are far.

**InfoNCE loss:**

$$\ell(x, x^+, x_1^-, \ldots, x_K^-) = -\log \frac{\exp(\text{sim}(z, z^+) / \tau)}{\sum_{i=0}^{K} \exp(\text{sim}(z, z_i^-) / \tau)},$$

where $z = f(x)$, $z^+ = f(x^+)$, $z_i^- = f(x_i^-)$, $\text{sim}$ is cosine similarity (or dot product), and $\tau$ is a temperature. This is the **NT-Xent** (normalised temperature-scaled cross-entropy) loss used in SimCLR, GraphCL, and most modern contrastive methods.

**Two views.** The anchor and positive are usually two **augmented views** of the same underlying sample. For graphs, the views can be:
- **Subgraph sampling**: $x$ and $x^+$ are subgraphs of the same underlying graph.
- **Edge perturbation**: $x$ and $x^+$ are the same graph with some edges perturbed.
- **Feature masking**: $x$ and $x^+$ are the same graph with some node features masked.
- **Diffusion / random walk**: $x$ and $x^+$ are two random-walk-induced subgraphs.

**For node-level contrastive learning**, the views are typically subgraphs sampled around each node (the "ego-network" approach).

> **Worked example.** GRACE (Graph Contrastive Representation Learning, Zhu et al. 2020) on the Cora graph. For each node $v$, two augmented views are generated by (a) randomly dropping edges with probability $p_e$, (b) randomly masking features with probability $p_f$. The InfoNCE loss is computed between the node's embedding in view A and the embeddings in view B. Negatives are all other nodes' embeddings in both views.

## 9.3 GraphCL: Graph Contrastive Learning

**Paper.** You et al., *Graph Contrastive Learning with Augmentations* (NeurIPS 2020). The first major graph-level contrastive method.

**Augmentations.** Four options:
1. **Node dropping**: randomly drop a fraction of nodes.
2. **Edge perturbation**: randomly add or remove edges.
3. **Feature masking**: randomly mask node features.
4. **Subgraph sampling**: sample a connected subgraph.

The two views are generated by applying two random augmentations. The InfoNCE loss is computed on the graph-level embedding (after readout).

**Properties:**
- Permutation invariant by construction.
- Choice of augmentation matters: for molecular graphs, subgraph sampling works well; for social networks, edge perturbation.
- The temperature $\tau$ is critical.

> **Worked example.** Two molecular graphs (caffeine and aspirin). Apply node dropping with $p = 0.2$ to each, getting $x_1, x_2$. Compute graph embeddings via GIN + sum readout. InfoNCE loss with $\tau = 0.1$: the model is trained so that $z_1$ (caffeine view 1) is close to $z_2$ (caffeine view 2) and far from any aspirin's embeddings.

## 9.4 GCC: Graph Contrastive Coding

**Paper.** [`2006.09963`](https://arxiv.org/abs/2006.09963) — Qiu et al., *GCC: Graph Contrastive Coding for Graph Neural Network Pre-Training* (KDD 2020).

**Approach.** Pretrain a GNN on ego-networks (subgraphs centered at each node) using contrastive learning. The "instance discrimination" task: distinguish ego-networks of different nodes.

**Two views per ego-network.** For each node $v$:
- Sample two random subgraphs $G_v^{(1)}$ and $G_v^{(2)}$ using **anonymous walks** (random walks of length $l$).
- The positive pair is $(G_v^{(1)}, G_v^{(2)})$.
- The negatives are ego-networks of other nodes.

**Why anonymous walks?** They capture the local structural pattern around a node, not the specific vertex identity. So the model learns structural features that transfer across graphs.

**Pretraining + finetuning.** Pretrain on a corpus of ego-networks. Finetune on a downstream task by adding a task-specific head. The pretrained GNN learns generalisable structural features.

> **Worked example.** Pretraining on a 100K-node academic graph. For each node, sample 10 ego-networks of 5 hops each. Pretrain a 5-layer GIN with InfoNCE. Then finetune on OGB-ArXiv for 40-class subject classification. The pretrained GNN typically gives 1-2% test accuracy improvement.

## 9.5 BGRL: Bootstrapped Graph Latents

**Paper.** Thakoor et al., *Large-Scale Representation Learning on Graphs via Bootstrapping* (ICLR 2022).

**Approach.** No negative samples! The model uses:
- An **online network** $f_\theta$ (the main model).
- A **target network** $f_\phi$ (EMA of the online network's parameters).
- The loss is the cosine similarity between the online and target embeddings, on two augmented views.

```
L = - sim(z_online^A, z_target^B) - sim(z_online^B, z_target^A)
```

where $z^A$ and $z^B$ are the online network's outputs on the two views, and $z_target$ is the target network's output.

**Why no negatives?** Avoids the need to sample negatives (which is hard for graphs because the same node may not have many "true negatives"). The target network's EMA provides a stable target for the online network.

**Properties:**
- $O(n^2)$ memory (no need for negative samples).
- Competitive with contrastive methods that use negatives.
- Inspired by **BYOL** (Bootstrap Your Own Latent) from vision.

> **Worked example.** On OGB-ArXiv, BGRL with GIN backbone reaches ~72% test accuracy — within 1 point of the best supervised GIN, with no labels at pretraining time.

## 9.6 GRACE, GCA, CCA-SSG: feature-aware contrastive methods

**GRACE** (Zhu et al. 2020): the basic framework; uses uniform random edge dropping and feature masking.

**GCA** (Zhu et al. 2021): extends GRACE with **adaptive** augmentations. Edge dropping probability depends on the edge weight (or some learned importance). Feature masking probability depends on feature importance. The result: more "informative" views.

**CCA-SSG** (Zhang et al. 2021): contrastive learning via **canonical correlation analysis**. Removes the dimension-wise correlation between embeddings while keeping the "task-relevant" information. No augmentation needed.

> **Worked example.** GCA on Cora. Edge dropping probability: $p_{uv} = \min(p_e, \text{deg}(u) \cdot \text{deg}(v) / 2m \cdot \alpha)$ — high-degree nodes' edges are dropped more aggressively (because they are less informative for distinguishing the node). Feature masking probability: $p_v = \min(p_f, \|\mathbf{x}_v\|_2 / \sum_u \|\mathbf{x}_u\|_2 \cdot \alpha)$ — nodes with high-norm features are masked more.

## 9.7 Masked autoencoding: GraphMAE

**Paper.** Hou et al., *GraphMAE: Self-Supervised Masked Graph Autoencoder* (KDD 2022). Inspired by BERT/MAE.

**Approach.**
1. **Mask** a random subset of nodes (e.g., 25% of nodes).
2. **Encode** the graph with a GNN (e.g., GIN, Graphormer).
3. **Decode** the masked nodes' features from the GNN's output.
4. **Loss**: MSE or cross-entropy between the predicted features and the original features.

**Why this works.** The encoder must learn to use the graph structure to reconstruct the masked features. This forces it to learn structural information.

**GraphMAE2** ([`2304.04779`](https://arxiv.org/abs/2304.04779), Hou et al. WWW 2023): adds a "latent representation prediction" loss, predicting the latent embedding of the masked nodes, not just the features. Stronger pretraining.

> **Worked example.** GraphMAE on the ZINC dataset. Mask 25% of atoms (replace their features with a learnable [MASK] token). Encode with 5-layer GIN. Decode each node's feature. Loss: MSE between predicted and original. After 100 epochs of pretraining, finetune on the supervised ZINC task. The pretrained GIN converges faster and reaches a better minimum.

## 9.8 Other pretraining objectives

**GPT-GNN** ([`1905.13728`](https://arxiv.org/abs/1905.13728), Hu et al. NeurIPS 2020). **Generative** pretraining for graphs. The model is trained to generate a graph by iteratively:
- Sampling a node's attributes.
- Sampling the edges from the new node to existing nodes.
The loss is the negative log-likelihood of the observed graph.

**Attribute masking + context prediction** (Hu et al. 2020, "Strategies for Pre-training GNNs"). Two supervised pretext tasks:
- **Attribute masking**: predict masked node attributes (similar to BERT).
- **Context prediction**: predict whether two subgraphs come from the same node's neighborhood or from different parts of the graph. (Similar to DeepWalk's negative sampling.)

**Multi-task pretraining.** Combine multiple pretext tasks with a weighted sum. E.g., InfoGraph (Sun et al. 2020) combines node-level and graph-level contrastive losses.

**Hybrid: contrastive + generative.** The state-of-the-art GFM pretraining uses a combination of:
- Contrastive loss on augmented views.
- Reconstruction loss on masked features.
- Optional: structural prediction (e.g., predict the degree of a masked node).

> **Worked example.** A "multi-task" GFM pretraining loss:
>
> $$\mathcal{L} = \alpha \mathcal{L}_{\text{contrastive}} + \beta \mathcal{L}_{\text{reconstruction}} + \gamma \mathcal{L}_{\text{structural}},$$
>
> with $\alpha = 1, \beta = 1, \gamma = 0.1$ as defaults. Train for 100 epochs on a corpus of 100K molecules. The resulting GNN/GT can be finetuned to any molecular property task.

## 9.9 Choosing a pretraining objective

| Objective | Best for | Pros | Cons |
|---|---|---|---|
| GraphCL | Graph-level tasks | Simple, well-tested | Augmentation choice is task-dependent |
| GCC | Node-level tasks, transfer | Learns structural features | Expensive ego-network sampling |
| BGRL | Large-scale, no negatives | Memory-efficient | May collapse without careful design |
| GraphMAE | Molecular, atomic features | Natural for features | Requires rich features |
| GPT-GNN | Generative, link prediction | Models full joint distribution | Hard to train |
| Multi-task | General-purpose | Most robust | Hyperparameter-sensitive |

**For GFMs.** The state-of-the-art GFMs use a multi-task pretraining loss combining contrastive + generative + structural objectives. See Ch 11 for specific examples.

> **Worked example.** GraphAny (a recent GFM) uses contrastive + structural prediction. GFT (the tree-vocabulary GFM) uses generative + structural. GFM-RAG uses contrastive + retrieval-augmented generation. There is no consensus yet on the "right" pretraining objective for GFMs.

## 9.10 The transfer learning protocol

**Step 1: Pretrain.** On a large corpus of graphs (e.g., 100K molecules from ZINC, or 1M ego-networks from a large academic graph), train the GNN/GT with a self-supervised objective for many epochs.

**Step 2: Freeze + linear probe.** Freeze the pretrained backbone. Train a linear head on the downstream task. Report accuracy. This isolates the quality of the representations.

**Step 3: Finetune.** Unfreeze the backbone. Train the whole model on the downstream task with a small learning rate. Report accuracy. This measures how well the pretrained weights adapt.

**Step 4: Few-shot.** Train on $k$ examples per class (e.g., $k = 1, 5, 10$) and report. The pretrained model should perform well even with little data.

**Reported numbers.** The literature reports two metrics:
- **Linear probe accuracy**: how good are the features?
- **Finetune accuracy**: how good is the whole model after finetuning?

A strong GFM should give both high linear probe and high finetune accuracy.

> **Worked example.** Pretrain a 5-layer GIN on 100K molecules with GraphMAE. Finetune on a 1K-molecule downstream task. The pretrained model converges in 50 epochs; the from-scratch model takes 200 epochs. Final test accuracy: pretrained = 82%, from-scratch = 78%.

## 9.11 Connection to language model pretraining

The NLP and graph pretraining are converging on similar ideas:

| NLP | Graphs |
|---|---|
| Word masking | Node feature masking |
| Next-token prediction | Graph generation (GPT-GNN) |
| Sentence contrastive (SimCSE) | Graph contrastive (GraphCL) |
| RoBERTa / BERT | GraphMAE |
| GPT-3 (decoder-only) | GraphGPT-style instruction tuning |
| Pretraining corpus: text | Pretraining corpus: molecular structures, networks, knowledge graphs |

The unification: a "graph" can be linearised into a sequence (e.g., SMILES for molecules, or a depth-first traversal of nodes), and then a standard transformer with masked language modelling can be applied. This is the **G-Retriever / LLaGA** approach (Ch 12).

> **Worked example.** SMILES for caffeine: `CN1C=NC2=C1C(=O)N(C(=O)N2C)C`. A standard transformer (e.g., RoBERTa-base) can be pretrained with masked SMILES reconstruction. After pretraining, the model has learned chemistry. The same model can then be finetuned for property prediction. This is the basis of **TAPE** (Transformer Encoder for Property Estimation) and many other "LLM-for-chemistry" methods.

## Exercises

1. **GraphCL on a small dataset.** Pretrain a GIN with GraphCL on a small molecular dataset (e.g., BBBP from MoleculeNet). Then finetune for the supervised task. Compare to from-scratch supervised training.

2. **BGRL on Cora.** Implement BGRL with a GIN backbone. Train for 200 epochs. Visualize the embeddings with t-SNE. Compare to a from-scratch GCN.

3. **GCC on ego-networks.** Sample 1000 ego-networks of 2 hops from Cora. Pretrain a 2-layer GIN with the GCC objective. Finetune on Cora node classification. Compare to a from-scratch GIN.

4. **GraphMAE on ZINC.** Implement GraphMAE with a GIN encoder. Pretrain on the ZINC training set (12K molecules) for 100 epochs. Finetune for the ZINC regression task. Compare to from-scratch.

5. **Augmentation ablation.** Pretrain a GIN with GraphCL using only one augmentation at a time (edge perturbation, node dropping, feature masking, subgraph sampling). Measure the linear probe accuracy on a downstream task. The "best" augmentation depends on the dataset.

6. **InfoNCE temperature.** Pretrain a GIN with different $\tau$ values (0.07, 0.1, 0.5, 1.0). Plot the linear probe accuracy. There is usually a "sweet spot" around $\tau = 0.1$.

7. **Multi-task pretraining.** Pretrain a GIN with a loss $\mathcal{L} = \mathcal{L}_{\text{GraphCL}} + 0.1 \cdot \mathcal{L}_{\text{attribute mask}}$. Compare to either alone.

8. **Read GraphMAE.** Read the GraphMAE paper. Identify the masking strategy, the encoder, the decoder, and the loss. The default masking is 25% of nodes; the default loss is scaled cosine error.

9. **Read the Hu et al. strategies paper.** The 2020 ICLR paper "Strategies for Pre-training Graph Neural Networks" introduced the attribute masking + context prediction pretraining. Read it and identify the two pretext tasks and how they combine.

10. **Linear probe evaluation.** Pretrain a GIN with any of the above methods. Freeze the backbone. Train a linear classifier on the downstream task features. Report the linear probe accuracy. A good pretraining should give linear probe accuracy within 5% of the finetuning accuracy.
